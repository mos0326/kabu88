# テーマ分析（Claude Code で実行・API料金なし）

依頼: $ARGUMENTS

このリポジトリの kabu88 は「AIは株価を当てる予言者ではなく、判断材料を整理する監査役」という設計です。
数値はすべて外部API（無料の Yahoo Finance・JPX公表データ、任意で J-Quants）からコードで取得し、あなた（Claude）は
定性情報の調査と、数値との突き合わせ（監査）だけを担当します。

## 0. 準備
1. `python -c "import yfinance, pypdf, xlrd"` が失敗したら `pip install -q -r requirements.txt` を実行する。
2. `python -m kabu.cli rules` を実行し、表示されたルールに例外なく従う。特に:
   - 数日〜数週間の値動き予想・目標株価・売買タイミング・売買の推奨は書かない
   - 数値は prepare が出力したもの以外を使わない（記憶の数値は使わない。Webで得た数値は出典つきで区別する）
   - 時間軸は数ヶ月〜数年。良い材料ほど「どこまで織り込まれていそうか」を数値で検証する

## 1. 定性リサーチ（WebSearch / WebFetch）
使用量を抑えるため、**検索は合計5回程度まで**にする。一次情報（決算短信・決算説明資料・有価証券報告書・中期経営計画・政府/業界統計）を優先する。
WebFetch が失敗するサイトは深追いせず、検索結果の要約で代用する。
1. テーマの中身: 何が・なぜ・どの期間で変わるか（市場規模・設備投資計画・政策などの裏付けを出典つきで）
2. バリューチェーン: どの工程・部材・サービスに需要が生まれ、どこがボトルネックか
3. 関連する東証上場企業: テーマ関連事業が実際に業績に寄与しているか（「関連銘柄」として名前が挙がるだけの企業と区別する）
4. 逆風・不確実性・テーマが崩れる条件

調べた内容を、出典（資料名・サイト名・日付）つきの箇条書きで `data/runs/pending/notes.md` に書く（フォルダがなければ作る）。

## 2. 関連企業を選ぶ
バリューチェーンの異なる段階から、東証上場企業を**最大5社**（ユーザーが指定したコードは必ず含める）。証券コードは4桁（英字を含む場合あり）。

## 3. 数値を取得する（無料）
```
python -m kabu.cli prepare <コード1> <コード2> ... --theme "<テーマ>"
```
標準出力のJSON（株価・バリュエーション・業績・需給・コード判定の監査フラグ・相場環境・不足データ）を読む。
標準エラーに表示される「保留中の分析ID」と「監査JSONの保存先」を控える。初回はJPXの信用残PDFの解析に15秒ほどかかる。

## 4. 監査JSONを書く
`python -m kabu.cli schema` で形式を確認し、その形式どおりのJSONを「監査JSONの保存先」に Write ツールで書く。
- companies には prepare で取得できた全銘柄を入れ、code は prepare の出力にあるものだけを使う
- quant_audit では、提供された数値（予想PER/PBR、1年・3ヶ月騰落率、200日線乖離、信用倍率、買残/出来高、空売り、会社予想の増益率・進捗率・修正）に具体的に触れ、監査フラグは必ず取り上げる
- cross_check には「ニュースは良いが需給は過熱」「話題だが業績寄与は小さい」のような定性と数値の食い違いを書く
- priority（深掘り/監視/優先度低）は調査の優先度であり、売買の推奨ではない
- data_gaps には不足していたデータ（prepare の data_gaps を含む）を書く

## 5. 保存する
```
python -m kabu.cli finalize <保留中の分析ID> --notes data/runs/pending/notes.md
```
スキーマエラーが出たら、JSONを直して再実行する。成功すると短期予測ガード（禁止表現の文の自動削除）を通したうえで
`data/runs/` に保存され、`reports/` に Markdown レポートができる。ダッシュボード（`streamlit run app.py`）の「履歴と検証」タブでも見られる。

## 6. ユーザーへの報告
レポートのパスと、要点（各社の調査の優先度・主な監査フラグ・定性と数値の食い違い）を短く伝える。売買の推奨や株価の予想はしない。
リポジトリは公開設定のため、`reports/` と `data/runs/` は git に含めない設定になっている（ユーザーが望まない限りコミットしない）。
